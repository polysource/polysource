## r/symfony post

```
Title: I shipped Polysource — drop-in filter enhancements for EasyAdmin

Hey r/symfony,

After spending too many hours wishing EA had Select2-style multi-selects
and date presets out of the box, I shipped polysource/easyadmin-filter-bridge.
It's a Symfony bundle that auto-tags 8 FilterEnhancers + adds 4 new filter
types (BetweenDateFilter, InFilter, NotNullFilter, FullTextSearchFilter).

What you get without writing a line of code:

- DateTimeFilter → date presets dropdown (today / 7d / 30d / this month / range)
- ChoiceFilter → Select2-style multi-select with chips above the table
- NumericFilter → between mode
- BooleanFilter → cleaner toggle
- TextFilter → optional full-text mode
- ComparisonFilter / ArrayFilter / EntityFilter → tightened forms

Plus a saved-views dropdown that persists filter combinations across
sessions (private / team / public scopes), all backed by a tiny
`SavedViewService` interface so you can swap the storage.

It's MIT, ships on Packagist as polysource/easyadmin-filter-bridge,
and supports EA 4.24+ and 5.0+ on Symfony 5.4|6.4|7.4 LTS, PHP 8.1+.

Composer:
    composer require polysource/easyadmin-filter-bridge

Drop-in install + screenshotted walkthrough:
    https://github.com/polysource/polysource/tree/main/docs/user/easyadmin-filter-bridge

Honest matrix vs upstream EA (what's improved, what's untouched):
    https://github.com/polysource/polysource/blob/main/docs/user/easyadmin-filter-bridge/whats-new.md

The bridge is one of two products in the Polysource monorepo (the other
is a standalone admin for non-Doctrine resources — Messenger failed
queues, Redis caches, S3 files, etc.). Both share the polysource/filter
primitive, so saved views work in plain Symfony forms outside EA too.

Happy to answer questions / take feedback. Issues + PRs welcome.

— Polysource maintainer
```

## EA repo Discussion (one-pager)

```
Title: polysource/easyadmin-filter-bridge — drop-in filter enhancements

Posting here because EasyAdmin contributors keep asking for date
presets, Select2-style multi-selects, saved views — but the
upstream scope is (rightly) different.

I shipped polysource/easyadmin-filter-bridge as a separate, MIT-licensed
bundle that auto-tags FilterConfiguratorInterface enhancers for the 8
built-in EA filter types, plus 4 new filter types and a saved-views
dropdown. Zero modification to EasyAdmin's source — works on EA 4.24+
and 5.0+.

Why I'm not proposing this upstream:
- The audience-capture window matters (EA 4 still on PHP 8.1 baseline).
- Saved views need their own storage abstraction → that doesn't belong
  inside EA core.
- Some users want the new filters, some don't — opt-in via a separate
  bundle is cleaner than adding switches to EA config.

Demo + screenshots: <link>
Honest per-filter matrix vs vanilla EA: <link>

Happy to chat if any of this overlaps with EA roadmap thinking.
```

- ❌ **Do not promote in EA issues/PRs.** It would feel like vendor
  spam in someone else's repo.

  It dilutes the headline; ship Announcement B 1-2 weeks later.
- ❌ **Do not over-claim.** "Replaces EA" / "Better than EA" are off
  the table — the bridge enriches, never forks. ADR-012.
