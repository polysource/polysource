# v0.1.0 pre-flight QA checklist

> Manual smoke-test pass that runs once **before** tagging `v0.1.0`. The
> 29 Panther tests + 15 real-container tests + 782 unit/functional
> tests already cover the engine; this checklist hunts for things only
> a human can spot (visual regressions, copy bugs, permission UX,
> empty states, browser-back behaviour).
>
> Audience: maintainer doing a final sweep on the showcase. Estimated
> time: 30-45 minutes if nothing is found; longer if any item flips
> red and a follow-up commit is needed.

## Setup (5 min)

```bash
make showcase-reset        # wipes volumes + reloads everything from scratch
open http://localhost:8084
```

Verify on screen:

- [ ] Page loads at `http://localhost:8084` and redirects to `/login`
- [ ] Login form renders (no broken assets, no console errors)
- [ ] Password reminder visible: 3 demo accounts use `shopco`

If any of the above fails, abort QA — the showcase is broken at the
foundation and tagging would be irresponsible.

---

## §1 · Sign in (3 min)

Login with each of the 3 demo accounts:

- [ ] `admin@shop.co` / `shopco` → home loads with all 6 widgets, sidebar
      shows every menu group (Catalog, Sales, Polysource standalone,
      Adapter resources)
- [ ] `ops@shop.co` / `shopco` → home loads, sidebar **omits** the
      `POLYSOURCE_AUDIT_VIEW`-gated audit log entry (and other admin-only
      menu items if any)
- [ ] `viewer@shop.co` / `shopco` → home loads, retry / dismiss /
      transition buttons are absent from listings
- [ ] Sign out button in sidebar reliably ends the session (re-hitting
      `/admin` after signout redirects to `/login`)

## §10 · Bulk jobs — `polysource/bulk-async` (3 min)

- [ ] Index shows ≥ 8 jobs across all 5 statuses (Pending, Running,
      Completed, Failed, Cancelled)
- [ ] Click a Running job → the detail page renders a **progress
      card** with: a status badge ("RUNNING"), a Bootstrap progress
      bar, and a counter `X / Y records` (the `_progress.html.twig`
      partial from `polysource/bulk-async`)
- [ ] Stay 10 seconds on the page → the progress bar advances
      without a full page reload. Verify in DevTools Network tab
      one of the two paths is active:
      - **Polling fallback**: recurring `GET /admin/bulk-jobs/{id}/progress`
        every ~2s, returning JSON with `processed`, `failed`,
        `progress` fields

        `/.well-known/mercure?topic=polysource/bulk-jobs/{actorId}/{id}`
        (only if the host has a Mercure hub wired)
- [ ] **Cancel** button visible on Running jobs only (not on Completed
      / Failed / Cancelled)
- [ ] After cancellation, refreshing the index shows status `Cancelled`
      with a partial progress count

## §15 · Saved views — `easyadmin-filter-bridge` (5 min)

This is the area that surfaced the most regressions during dev — slow
down here.

On `/admin/order`:

- [ ] Open the filters modal, apply a non-trivial filter set (e.g.
      `status = pending`, `total > 100€`, `createdAt this_month`)
- [ ] Click **Saved views ▾** → **Save current as view…** → name
      "QA test view 1" → save → flash success → dropdown closes
- [ ] Reopen the dropdown → "QA test view 1" appears in the list
- [ ] Apply a **different** filter set (status = shipped, total < 50€)
- [ ] Save as "QA test view 2"
- [ ] Click "QA test view 1" → **single click** applies the saved
      filters (NOT 2 clicks — that bug was fixed in commit 3f91cce)
- [ ] Switch to "QA test view 2" → also single-click apply
- [ ] Browser back button → previous filter state restored, chips bar
      reflects the previous view
- [ ] Hover the trash can next to "QA test view 1" → tooltip → click
      → confirms deletion → dropdown updates without page reload

As `ops@shop.co` (in a different browser / private window):

- [ ] "QA test view 1" / "QA test view 2" are **not visible** (they are
      private to admin's identity)
- [ ] Direct URL `?view=<id-of-admin-view>` returns 403 (theft guard
      from `SavedViewAccessDeniedException`)
