# Installing `polysource/audit`

This page covers the install path for a Doctrine-backed Symfony app.
Apps without Doctrine see a smaller wiring (NullAuditLogger by
default) — see [extending.md](./extending.md) for that case.

## 1. Composer

```bash
composer require polysource/audit
```

Requires `polysource/core` (already a transitive dep if you have
`polysource/symfony-bundle`) and `doctrine/orm` for the default
Doctrine logger + browsable audit log resource.

## 2. Register the bundle

Add to `config/bundles.php`:

```php
return [
    // …existing bundles…
    Polysource\Audit\PolysourceAuditBundle::class => ['all' => true],
];
```

Discoverable via `bin/console polysource:plugins:list` (per
[ADR-018](../../adr/0018-admin-plugin-interface-and-public-contracts.md)).

## 3. Map the entity

Tell DoctrineBundle where to find the audit entity. In
`config/packages/doctrine.yaml`:

```yaml
doctrine:
    orm:
        mappings:
            PolysourceAudit:
                is_bundle: false
                type: attribute
                dir: '%kernel.project_dir%/vendor/polysource/audit/src/Storage/Doctrine'
                prefix: 'Polysource\Audit\Storage\Doctrine'
                alias: PolysourceAudit
```

If you already use a `default` mapping that includes
`%kernel.project_dir%/src/Entity`, leave it alone — Doctrine merges
all mappings.

## 4. Create the table

```bash
# Production: generate a migration and review it.
bin/console doctrine:migrations:diff
bin/console doctrine:migrations:migrate

# Dev / test: schema:create works for fresh DBs.
bin/console doctrine:schema:create
```

The resulting table:

| Column | Type | Notes |
|---|---|---|
| `id` | `string(36)` | UUID v7 generated by `ActionAuditSubscriber` |
| `occurred_at` | `datetime_immutable` | UTC-normalised by the VO |
| `actor_id` | `string(120)` | matches `UserInterface::getUserIdentifier()`; `__anonymous__` for unauthenticated calls |
| `actor_label` | `string(120)` nullable | display name; `null` if unavailable |
| `resource_name` | `string(120)` | e.g. `failed-messages`, `audit-log`, an EA `entityFqcn` |
| `action_name` | `string(120)` | the action's slug — `retry`, `dismiss`, `export-csv`, … |
| `record_ids_json` | `text` | JSON `list<string>` — empty for global actions |
| `outcome` | `string(16)` | `success` / `failure` / `exception` |
| `message` | `text` nullable | the `ActionResult::message` (sanitised before storage) |
| `duration_ms` | `integer` | wall-clock around the callable invocation |
| `context_json` | `text` | JSON `map` — `ip`, `userAgent`, `requestId`, optional `actionContext` / `errorClass` / `errorTrace` |

3 indexes optimise the canonical queries:
- `idx_occurred_at` — chronological scrolling
- `idx_actor_resource` (actor_id, resource_name) — "what did Alice do on orders?"
- `idx_resource_action` (resource_name, action_name) — "all retries on failed-messages this week?"

## 5. Permission gate

The browsable resource declares `POLYSOURCE_AUDIT_VIEW`. Wire a voter
to grant it:

```php
// src/Security/AuditVoter.php
final class AuditVoter extends Voter
{
    protected function supports(string $attribute, mixed $subject): bool
    {
        return 'POLYSOURCE_AUDIT_VIEW' === $attribute;
    }

    protected function voteOnAttribute(string $attribute, mixed $subject, TokenInterface $token, mixed $vote = null): bool
    {
        return \in_array('ROLE_COMPLIANCE', $token->getRoleNames(), true);
    }
}
```

Or extend an existing `POLYSOURCE_*` blanket voter — that's what the
messenger-demo does (every `POLYSOURCE_*` attribute is granted to
`ROLE_ADMIN`).

## 6. Smoke-test

```bash
# Trigger an action via the admin UI (e.g. retry a failed message).
# Then list the audit log:
bin/console doctrine:query:sql "SELECT id, actor_id, resource_name, action_name, outcome FROM polysource_audit_log ORDER BY occurred_at DESC LIMIT 10"
```

Or visit `/admin/audit-log` (with `POLYSOURCE_AUDIT_VIEW` granted)
to see the browsable index with filters.

## 7. EasyAdmin integration (optional)

If your host runs EasyAdmin alongside Polysource, EA's CRUD edits
(Edit / New / Delete on Doctrine entities) bypass
`polysource/symfony-bundle::ActionController` and are NOT picked up
by `ActionAuditSubscriber`. To audit them, the bundled
`EasyAdminAuditSubscriber` listens to EA's three lifecycle events and
emits one audit entry per CRUD operation.

Auto-wired the moment `easycorp/easyadmin-bundle` is installed —
service registration in `services.php` is gated on
`class_exists(AfterEntityUpdatedEvent::class)`. Hosts without EA see
no overhead.

What lands in the audit log per EA edit:

| Field | Value |
|---|---|
| `resource_name` | The entity's FQCN (e.g. `App\Entity\Order`) |
| `action_name` | `create` / `update` / `delete` |
| `actor_id` / `actor_label` | From `AuditActorInterface` (Symfony Security by default) |
| `record_ids_json` | `[<id>]` — best-effort via `getId()` / `getUuid()` / `id` / `uuid` property |
| `outcome` | Always `success` (EA dispatches lifecycle events only on the success path) |
| `context_json` | `ip`, `userAgent`, `requestId` |

Hosts whose entities use exotic identifiers (composite keys, factory
methods, …) subclass `EasyAdminAuditSubscriber` and override
`extractIdentifier()`.
